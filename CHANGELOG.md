## [0.1.6] - 2026-08-08

**The first release that anyone but a Windows user can install.** The macOS
disk image and the Linux tarball ship here, and they ship labelled: nobody has
run either one on the hardware it targets, and every backend on those two
platforms is verified by types, pure tests, CI and primary sources only.

They were held for exactly that reason through two closed phases, and the hold
turned out to be self-defeating. The macOS DDC path leaves "experimental" only
on independent community confirmations, and those come from other people's
machines running an artifact that was never on the Releases page: the condition
for releasing was confirmation, and the mechanism for getting confirmation was
releasing. [ADR-0024](docs/adr/0024-preview-artifacts-on-the-patch-train.md)
breaks that loop and re-maps `v0.2.0` and `v0.3.0` to mean **hardware-confirmed**
rather than first-shipped.

For Windows this is a smaller release than that makes it sound, and a real one:
`duja.exe` is **19 % smaller** than at `v0.1.5`, quitting Duja no longer flattens
the gamma of displays it never touched, and `config.toml` is size-capped before
it is read.

## [0.1.5] - 2026-07-26

A patch for a defect found in continued real-world use: a monitor with working
hardware brightness control could get stuck reporting itself as "software-only"
during a long session, and only restarting Duja cleared it.

### Added

- **app**: A tray **Restart** item, between "Restore screen" and "Quit". The
  replacement instance is spawned *before* the current one quits, so a failed
  spawn leaves Duja running rather than gone, and it waits for the outgoing
  instance to release the single-instance lock before taking over. The outgoing
  instance still exits cleanly — restoring gamma and overlays and flushing state
  first — so the fresh instance adopts the same levels (#78)

### Documentation

- The README leads with a warmer, benefit-first introduction and carries real
  screenshots of the flyout and settings window in place of the placeholder art
  (#72)
- A post-1.0 [future-vision](docs/future-vision.md) brainstorm of the wider
  monitor-capability surface Duja could grow into: the full DDC/CI feature set,
  OS-level colour and display control, automation, and integrations. A triage
  menu, not a commitment (#79)

### Fixed

- **ddc,app**: A live monitor no longer sticks as "software-only". The runtime
  "no working hardware" downgrade is sticky: it is re-evaluated by a fresh worker
  probe (sleep/wake, a display-change re-enumeration, or an
  unresponsive-to-responsive recovery), or by the poll-driven self-heal — which
  needs the panel to actually *move* to the level Duja last wrote while the
  flyout is open and polling, so neither path is guaranteed to fire in a given
  session. If the capability string could not be read, the fallback probe treated
  a *failed* brightness read as brightness being *absent* and reported it through
  a successful result, so an external monitor that simply was not answering at
  that moment (waking from DPMS, or a momentarily busy DDC bus) was mislabeled,
  in practice until Duja was restarted. Brightness is now load-bearing: a failed
  read is surfaced as inconclusive, never as a false "absent". A definitive
  verdict comes only from a successful capability read that omits brightness, or
  the `ddc_broken` quirk, and a genuinely dead panel is still caught by the
  retried first-write check (#78)

## [0.1.4] - 2026-07-19

A dark rebrand, plus the multi-monitor follow-ups from continued laptop testing:
mirror/duplicate mode is now one clean control, and "software-only" displays can
no longer strand their slider.

### Added

- **ui/app**: A dark brand identity. *Duja* (دُجى) is Arabic for *darkness*, and
  the mark now leans into it — the whirlpool inverted to near-black gems whose
  spiral seams glow in the four accent hues (ruby, gold, emerald, sapphire), with
  an iridescent rim tracing the monitor silhouette. The executable/installer
  icon, the README hero, and the social card all regenerate from one code source
  (`dark_whirlpool_rgba`) and are drift-tested, and the README carries the origin
  of the name (#70)

### Changed

- **ipc**: The app↔`dujactl` protocol is bumped to v2. The `DisplayKind`
  `SoftwareOnly` variant is gone; runtime control-mode now rides a dedicated
  `software_only` flag on the display DTOs, so a display's physical provenance
  (internal/external) and its control mode are reported independently (#67)

### Fixed

- **app**: Mirrored/duplicate displays are merged into a single control. In
  Windows *Duplicate* mode the cloned panels share one framebuffer, so the old
  per-panel rows stacked two overlays on the same pixels (double-dimming) and
  offered redundant sliders. Duja now groups a mirror set by its shared surface
  and drives it once — all-hardware sets drive every member, otherwise one shared
  overlay with hardware members pinned to maximum — keyed to the stable GDI
  device so a hot-plug that moves the group's anchor no longer snaps your level
  back to 100% (#66)
- **ui**: A "software-only" display (a TV, dock, or capture card with no hardware
  control) can no longer be left stranded. Its "Software dimming" pill is forced
  on and disabled rather than being freely toggleable — turning it off used to
  leave the slider with nothing to drive — and the slider dims through the overlay
  across the full range (#67)

## [0.1.3] - 2026-07-19

A follow-up patch to the v0.1.2 multi-monitor wave. Real-hardware laptop testing
showed the built-in panel could disappear from the tray entirely on machines
whose backlight is driven by the GPU/OEM stack rather than ACPI/WMI.

### Fixed

- **ddc**: A laptop's internal panel no longer vanishes when Windows exposes no
  WMI brightness for it. v0.1.2 skipped internal panels from the DDC path on the
  assumption the WMI panel backend would own them, but on many laptops
  `WmiMonitorBrightness` is empty (a GPU/OEM-driven backlight), so the panel
  appeared in neither list. DDC now surfaces the internal panel as a fallback —
  flagged internal and bound only to a physical-monitor handle left over after
  external pairing, so mirror-mode external routing is unchanged — and the
  discovery merge keeps it only when WMI sees no panel (WMI stays authoritative
  when it can drive the panel). `open_controller` prefers WMI, then falls back to
  DDC-over-eDP, then to the engine's software overlay, so the built-in screen is
  always present and controllable (#64)

## [0.1.2] - 2026-07-18

A multi-monitor & capability patch release. Real-hardware testing on a laptop
(internal panel + one external monitor, including Windows *Duplicate*/mirror mode
and the *Link all* feature) surfaced a cluster of defects in display identity,
capability detection, and linked control — all fixed here test-first, each behind
a separate adversarial review, then a post-merge audit + holistic integration
review of the combined result (which caught and corrected an over-broad
enumeration probe and a reattach-recovery gap before this tag).

### Fixed

- **ddc**: A laptop's internal panel is no longer mislabeled "External" — DDC
  enumeration reads each output's `outputTechnology`, classifies internal/embedded
  panels, and deduplicates them against the WMI panel backend, so the built-in
  screen appears exactly once as "Built-in" (#58)
- **ddc**: Windows *Duplicate* (mirror) mode now shows one controllable row per
  physical panel instead of collapsing to one — enumeration emits every physical
  monitor behind a shared `HMONITOR`, binding the external's handle via a paced,
  retried DDC probe (identical mirrored pairs keep the existing twin-slot logic);
  the probe is bounded to real ambiguities so a silent internal-panel handle can
  no longer stall enumeration (#61, #62)
- **engine**: A monitor with no working hardware brightness now auto-switches to
  full-range software dimming. The per-monitor worker probes on open and verifies
  its first write — retried with back-off, so a slow panel (behind a dock/MST/KVM)
  is never mistaken for a dead one — downgrading to software-only on a genuine
  no-op, with an in-session self-heal that restores hardware control if the panel
  is later seen to move; a physical replug re-runs detection cleanly (#59, #62)
- **ui**: "Link all" preserves each monitor's relative offset instead of snapping
  every slider to one value — it wires the drift-free `SyncGroups` engine, so the
  gaps hold and re-open exactly after saturating at a bound (#57)
- **ui**: Linked sliders now track the dragged one instantly instead of gliding —
  the 160 ms premium glide is suppressed for a link-originated fan-out while an
  external-button reflection keeps it (#60)

## [0.1.1] - 2026-07-17

A correctness, safety, and supply-chain patch release: the first post-v0.1.0
deep review (14 module reviewers, adversarially verified) found a batch of
cross-crate seam and lifecycle defects, all fixed here test-first.

### Security

- **ci**: The release pipeline no longer interpolates `github.*` context (the
  tag name) into privileged `run:` bodies — a crafted tag could otherwise inject
  shell into the job that holds the minisign secret. It now re-runs the full CI
  gate (cargo-deny + clippy + tests) on the tagged commit before publishing,
  wipes the signing key on the failure path, pins the Inno Setup version with a
  required checksum, and builds hermetically without a mutable cache (#47)
- **platform,app**: `dujactl` now verifies the pipe server's token-user SID
  before trusting a connection, so a same-user pipe squatter can no longer
  intercept control traffic; on mismatch it falls back to the direct backend (#55)

### Fixed

- **dujactl**: `set all` works over IPC again — it reconnects per request instead
  of reusing a single one-request-per-connection stream (it silently failed
  against a running app before) (#46)
- **app**: Worker lifecycle is safe on detach, open-failure, and quit — a bounded
  shutdown join no longer hangs app exit on a wedged driver call, a detached
  worker can never become a second writer to a panel, a failed controller open
  greys the display and recovers instead of silently losing control, and
  watchdog recovery restores the user's level instead of relearning it
  (ADR-0017) (#48)
- **dimmer**: Overlay windows are destroyed on a creation-failure path (no more
  leaked windows), capture-exclusion failure degrades to a working dim instead of
  none, the gamma crash marker is preserved when a restore fails (the never-brick
  net), and overlay apply/clear can no longer freeze the UI thread on a wedged
  worker (#49)
- **app**: The HDR gamma verdict is re-probed live instead of frozen at launch,
  so turning HDR on after start routes to the overlay instead of an ineffective
  gamma ramp; `begin_quit` preserves the crash marker on a failed restore (#53)
- **core**: Serial-less display identity keys on the 128-byte EDID base block
  only, so a truncated or extension-carrying read of the same panel no longer
  splits its identity and loses its per-monitor config (#50)
- **ui**: A hot-plug during a slider drag no longer retargets the drag to the
  wrong monitor (the row model is order-stable by id); the settings input dropdown
  keeps its selection and stops resetting mid-click; the resize grip no longer
  hijacks scrollbar drags (#52)
- **ddc**: A hardware-reported continuous max of 0 is floored to 1, so a corrupt
  DDC reply can no longer drive a panel to its darkest level regardless of the
  slider (#54)
- **app**: The update check treats a future last-check timestamp as due (a
  backward clock can no longer wedge it off), motion detection defaults to on when
  the OS query fails, logging falls back to the temp root when no home dir
  resolves, and the open flyout re-applies its work-area height cap on a
  resize-while-visible so it can't grow off-screen (#51)
- **platform**: The Windows installer detects a running instance via a fixed-name
  guard mutex (`AppMutex`) and prompts to close it, instead of silently failing an
  in-place upgrade (#55)

### Changed

- **ci**: Release checksums are written LF-only so `sha256sum -c` passes on Linux
  and macOS; a drop-in, secret-gated Azure Trusted Signing step is staged so
  Authenticode signing can be enabled later with no workflow edit (#47)

### Documentation

- **adr**: ADR-0017 (engine shutdown & worker-lifecycle contract), ADR-0018
  (app-owns-continuum / engine-owns-pacing), ADR-0019 (version ladder & release
  trains), ADR-0020 (release integrity & signing readiness); a new
  `docs/release-checklist.md` runbook
